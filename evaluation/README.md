# evaluation/

The Python analysis side. It never runs the estimator: it reads run records written by the Java
drivers and datasets written by the ingest tools, and computes metrics, tables and figures.

| Path | Contents |
|---|---|
| `naveval/` | Trajectory evaluator: dataset and run-record loaders with contract checks, Sim(2) and fixed-parameter alignment, ATE/RPE, heading, scale and failure metrics, MARS-LVIG and MCAP ingest, and the skyline-retrieval evaluator used by `hsreloc`. |
| `tests/` | `naveval` test suite and its fixtures. All fixtures are synthetic or generated by the code under test. |
| `configs/` | `naveval.evaluate` configs for the MARS-LVIG windows reported in the thesis, plus the golden fixture config. Paths inside resolve relative to the config file. |
| `eval_configs/` | Java run configs (`VoRunnerApp`), grouped by experiment. Paths inside resolve relative to the repository root, so run the Java drivers from there. `int/README.md` describes the integration configs one by one. |
| `confidence_configs/` | Calibration files for the optional, unvalidated confidence scorer. Read by Java tests. |
| `tools/` | Per-experiment scripts. `docs/reproducing.md` maps them to the reported results. |

Where the datasets come from is described in `docs/data.md`, and the evaluation commands in context
in `docs/workflows.md`.

Tests (from this directory; the tool tests under `tools/` are collected too):

```bash
python -m pytest -q
```

Evaluate a run record against a dataset:

```bash
python -m naveval.evaluate --config configs/eval-golden.json --out ../evaluations/golden
```

The evaluator refuses malformed inputs instead of guessing: a truncated run record, a dataset whose
frame or heading convention is not ENU / clockwise-from-North, or a ground-truth quality class it
cannot interpret are errors. Numbers from different evidence tiers (synthetic, simulator, recorded
flight) are never pooled in one table.
